## 💡 Decisions Made & Key Discussions

### 1. Git Workflow
* **Branches:** Everyone works on their own branch instead of pushing to `main`, so changes can be reviewed before merging. Naming convention: `name-feature` (e.g. `klara-user`, `klara-application`).
* **Reviews:** Reviewing each other's work is part of how we are assessed, so all changes should go through a pull request.

### 2. Backend & Repo Structure
* **Backend schema:** Klara added the backend structure and data model to the README. It is detailed for a README, so we will revisit what stays there once the app is built.
* **Building plan:** Klara added a rough building plan to `project_management/`. It will be reformatted as a list and planned week by week (one topic per week), since some tools, like Docker, are only covered in a few lessons.

### 3. Frontend–Backend Conventions
* **Shared naming doc:** We need an agreed list of what each page needs from the backend (routes, methods, arguments) and how things are named, kept in one document in the repo so the frontend does not need to read through backend files.
* **Order of work:** The backend defines names first; the frontend follows about one feature behind.

### 4. MVP Scope & Design
* **MVP:** Application tracker + social features first. The document (CV) manager is left until after the MVP, as the TA advised.
* **Open question:** How adding an internship works (paste a link directly into the table, or a pop-up with more fields).
* **Frontend:** Noku will design the registration and login pages and any screens needed for the MVP, designing in Figma and building with only what we used in class (HTML, CSS, JS) so everyone can understand the code.

### 5. Task Assignment & Tracking
* **Roles:** Klara on backend, Noku on frontend, Ahmed and Litong on the remaining work (Ahmed leaning towards backend support).
* **Process:** Timu acts as project manager this week: lists the tasks, gives a 1-day window for people to volunteer, then assigns the rest.
* **Review before building:** Everyone reviews and agrees on Klara's and Noku's work before more is built on top of it.
* **Ticket tracking:** Linear and Jira were discussed, but Prof advises keeping everything in GitHub, so we will start with GitHub issues and revisit if needed.
