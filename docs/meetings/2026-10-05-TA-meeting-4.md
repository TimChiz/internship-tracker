## 💡 Key Feedback & Guidelines

### 1. Project Scope & Technical Expectations
* **Project Novelty:** The project does not need to be completely novel; focus on high code quality, clean architecture, and professional execution.
* **Team Project Awareness:** Every team member must understand the state of the entire project and be able to explain the architecture during check-ins and evaluations.
* **Evaluator Prerequisites:** Make running the application effortless for graders. Ensure there are zero complex prerequisites, or provide explicit, step-by-step setup documentation.

### 2. AI Integration & API Rules
* **No Key Requirements for Evaluators:** Evaluators must be able to run and grade the app without entering personal API keys or registering for third-party services.
* **Ollama for Local AI Execution:** Research and utilize **Ollama** to run open LLMs locally on host machines during testing and live demos.
* **Potential AI Features:**
  * Auto-updating application statuses via email/calendar parsing (e.g., automatically updating status to "Rejected" upon receiving a rejection email).
  * Dynamic resume customization tailored to specific job postings.
* **Scaling Concept:** In project documentation, frame paid API key usage as a "premium/paid tier" scaling model for real-world deployment.

### 3. Development Timeline & User Testing
* **Early MVP:** Ship a functional MVP as early as possible to allow time for feature pivots based on initial feedback.
* **Buffer Period:** Reserve dedicated time before the final submission strictly for bug fixing, UI polish, and comprehensive testing.
* **Continuous User Testing:** User testing is critical and must occur continuously after every new feature release.
* **Diverse User Base:** Use **different test users** for each testing round to gather unbiased feedback.

### 4. Development Workflow & Team Dynamics
* **Peer Code Reviews:** Enforce strict GitHub rules—no code can be merged into the `main` branch without at least one peer review.
* **Clear Task Mapping:** Maintain a transparent roadmap by defining and assigning both current and future backlog tasks on the GitHub Kanban board.
* **Interdependent Work & Communication:** Team tasks are closely linked; maintain frequent communication, keep team members accountable, and hold joint co-working sessions.
